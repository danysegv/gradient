## The person layer (new, 09-11)

### What was asked
Luma wanted a second profile — `veronagarcia` — to log in and out of alongside `lumalhaes`.

### What already existed — the feature itself is zero code
`lib/clip-auth.ts` was built for this. `CLIP_CURATORS` is a `name:secret,…` list; `resolveCurator`
maps a submitted password to a curator in constant time; the cookie stores `name.<hash>` bound to
that curator's secret, so rotating one signs out only that one; `/clip` already has a **Sign out**
button. `/curator/[name]` is dynamic and `notFound()`s until a name has clips, so a new profile
appears by itself and leaves no ghost.

**Adding a curator is one entry in `CLIP_CURATORS`, locally and in Vercel.** That is the whole
feature. `getCurators()` caches at module level, so a change needs a redeploy (or a dev-server
restart) to take effect.

### Why a person layer was built anyway
Two metrics reason about **plurality** and both read the *name* on the clip:

- **`computePanelComposition`** — total-variation distance between the window's curator mix and the
  all-time mix. Its job is to notice when a velocity number describes a change of *people* rather
  than a change of taste.
- **`computeBalancedVelocities`** — **this is the one that bites.** An equal-weight mean over
  curators. A person with two identities gets **two votes** in an average built to give each person
  one. And splitting halves each identity's volume: either half under `MIN_CURATOR_RECENT_VOLUME`
  (30) is disqualified, and if both are, the qualifying count drops below two and **every tag's
  balanced number silently becomes `null`**. A test covers exactly that.

**Measured before building:** at the 09-26 window a fourth name moves drift **identically** whether
the clipping is filed under a new name or an existing one — 20 applications reads 16.67% either way,
50 reads 17.80%. `base_count` is all-time and *includes* the recent window, so a new identity enters
both sides of the fraction at once. The gate was not approximate here, it was **blind**.

### What shipped
| | |
|---|---|
| `curator_identities` | `name → person`. RLS on, **no policy**, revoked from `anon` and `authenticated`. The one table that would link a pen name to a human. |
| `panel_composition(window_days)` | **SECURITY DEFINER** so it reads that table across RLS. Returns aggregate counts per person, never the mapping. **The function is the privacy boundary.** |
| `curator_composition` | **Untouched, still by name.** Feeds the `/curators` display — one row per profile. |

Two RPCs because **display and integrity are different questions**. Person keys never reach the
browser: `app/page.tsx` reduces to one boolean; `/curators` renders drift and the gate light only.

Verified: `set role anon` → `panel_composition(30)` returns rows; `set role anon` →
`select from curator_identities` → **`insufficient_privilege`**.

### Current mapping — nothing maps to anything else
```
danysegv        → daniela         own person
lumalhaes       → luma            own person
igorsurrealism  → igor            own person
veronagarcia    → veronagarcia    own person   ← decided 09-11: a FOURTH USER, not Luma
```
An earlier decision that day had `veronagarcia → luma`; **it was reversed.** Treat her as a separate
curator. The person layer is in place and correct, and right now it is an identity function.

**The self-mapping row is deliberate.** `coalesce(ci.person, c.clipped_by_name)` makes a missing row
and a self-mapping behave identically — but **an absent row is indistinguishable from a typo**. A row
saying "this name is its own person" is a statement; silence is not.

### Two design choices worth keeping
- **The identity map is a REQUIRED parameter** on both functions, not optional. An optional map is
  the `publishedTags`/`allTags` failure again: a caller that forgets it gets a plausible, internally
  consistent, wrong answer. Required means `tsc` names every caller that forgot. **It named four.**
- **`coalesce`, not an inner join.** An unmapped curator is their own person. Dropping them would
  shrink the panel silently and flatter every figure built on it.

`scripts/panel-report.ts` reads with the anon key, which by design cannot see the mapping. It now
loads it with the service role and, when that key is absent, **prints that it is reporting a
NAME-level panel** rather than quietly reporting the number this change exists to correct.

### 🔴 Incident: the two-letter typo (caught clean)
`.env.local` had **`veronagracia`**; the database had **`veronagarcia`**. Luma would have logged in
fine, her clips would have been stamped `veronagracia`, no mapping row would have matched, and she
would have become a *different person from the one intended* — with no error anywhere. Nothing had
been clipped under either spelling. `.env.local` was corrected; **Vercel was never seen.**

**Structural gap, not yet closed:** nothing ties `CLIP_CURATORS` to `curator_identities`. A name can
exist in one and not the other, and the system cannot distinguish a typo from a genuinely new
person. Proposed but not built: `/clip` displaying who you are clipping **as**, so a misspelled or
unmapped name is visible at first login instead of being discovered in the numbers weeks later.

## How the freeze works (unchanged)

`tags.published_at` is the whole mechanism. **Null = incubating.**

| | incubating tags |
|---|---|
| classifier applies them | **yes** — it sees all 56 non-`format_motion` tags |
| shown on clips, `/clip/[id]`, hover chips | **yes** |
| filter chips | **yes** — filtering is navigation |
| reference count | **yes** — a count, not a rate |
| **velocity / share** | **no** — `getConfidence` withholds it, label reads **Incubating** (in Bone) |
| **any denominator** | **no** — callers sum over `is_published` rows only |
| trending rail | **no** — that rail *is* the radar |
| panel drift, `/genome`, curator breakdown, clip stats | **no** — published-only |

### ⚠ The single most dangerous line in the product
```ts
const publishedTags = allTags.filter((t) => t.is_published);
const baseTotalRefs = publishedTags.reduce((n, t) => n + t.clip_count, 0);
```
Swap `publishedTags` for `allTags` in any of those reduces and the incubating vocabulary silently
re-enters the denominator. Nothing looks wrong, every incumbent quietly loses share, and every figure
is internally consistent and wrong. `lib/taxonomy-freeze.test.ts` asserts the filter on all three
surfaces.

## Environment gotchas (hard-won — do not rediscover)

**New 09-11:**
- **`.git` on the mount has ~170 `tmp_obj_*` and `*.lock.trash.*` files.** The mount cannot `unlink`,
  so git leaves debris on every commit. **Only the Mac can delete them.** Harmless but growing.
- **When git refuses to commit** (`Unable to create '.git/index.lock'`), sweep with
  `mv .git/index.lock .git/index.lock.trash.$RANDOM` — also `.git/HEAD.lock`. Then retry.
- **`tags` has no `axis` column — it is `"group"`**, and `group` is reserved, so it must be quoted.

**Carried forward:**
- **`device_bash` runs in a Linux VM, not macOS.** It cannot run `npm run dev`/`build` (no SWC for
  linux/arm64 against macOS `node_modules`) and has **no network route to Supabase**. It CAN run
  `tsc`, `eslint`, `npm test`, `node`, `python3`, `git`. **The build must run on the Mac.**
- Commits from the bridge need `git -c user.name=... -c user.email=...` inline.
- **Every scripted string replacement must `assert old in s` first**, and assert the count is 1.
- **Anthropic API credits are separate from a Claude Pro subscription.** The classifier dies with
  `400 invalid_request_error: "credit balance is too low"`.
- **A background job that cannot report its own failure is worse than a slow one.** The first clip of
  every batch is classified **inside the request** so its error reaches the screen.
- **But a probe that aborts on ANY failure is the opposite bug.** Per-clip image failures **park**;
  account-level failures **abort**. Unknown errors abort deliberately.
- **`create or replace function` cannot change a return type.** `drop function` first, then re-`grant`.
- **Postgres grants `EXECUTE` to `PUBLIC` by default** — new RPCs land reachable by `anon` unless
  revoked.
- **WebFetch caches 15 minutes per URL.** A just-deployed page can read stale.
- **JSX strips leading whitespace on wrapped lines** — use explicit `{" "}`.
- **Claude-in-Chrome tab IDs go stale between turns.** Screenshot immediately before clicking.
- Pinterest (`i.pinimg.com`) and `londonartfair.co.uk` are blocked by browser domain permissions.
- **PostgREST caps rows at 1000 without erroring** and serialises `bigint` as a string — `Number()`
  once, at the boundary.
- **`project_write` has no in-place patch** — a project doc must be rewritten whole.
- **Daniela does every `git push` herself. Never authenticate as her.**
