## How the freeze actually works now

`tags.published_at` is the whole mechanism. **Null = incubating.**

| | incubating tags |
|---|---|
| classifier applies them | **yes** — no env flag, no write-path guard, it sees all 56 non-`format_motion` tags |
| shown on clips, `/clip/[id]`, hover chips | **yes** (these join `clip_tags → tags` directly) |
| filter chips | **yes** — filtering is navigation |
| reference count | **yes** — a count, not a rate |
| **velocity / share** | **no** — `getConfidence` withholds it, label reads **Incubating** (in Bone) |
| **any denominator** | **no** — callers sum over `is_published` rows only |
| trending rail | **no** — that rail *is* the radar |
| panel drift, `/genome`, curator breakdown, clip stats | **no** — published-only, untouched |

`tag_velocity_counts` and `curator_tag_counts` return **all 59 tags with an `is_published` flag**;
the split lives in the callers. Everything that produces a figure and nothing else stayed
published-only.

### ⚠ The single most dangerous line in the product
```ts
const publishedTags = allTags.filter((t) => t.is_published);
const baseTotalRefs = publishedTags.reduce((n, t) => n + t.clip_count, 0);
```
Swap `publishedTags` for `allTags` in any of those reduces and the incubating vocabulary silently
re-enters the denominator. Nothing looks wrong — the new tags still show no numbers — and every
incumbent quietly loses share, with every figure internally consistent and all of them wrong. Tests
in `lib/taxonomy-freeze.test.ts` assert the filter exists on all three surfaces.

## Phase 04 — built, not wired (`de109f8`)

**Nothing calls it.** The 09-26 board launches on the locked metric (verified safe: max age artifact
0.33 pts, no reordering, no sign flips). Wiring before launch would change a signed-off board. It is
a one-line switch in October.

Two artifacts, different causes, neither fixes the other:
- **Debut (4.1)** — baseShare is a share of ALL-TIME applications; a tag younger than its axis has a
  suppressed baseline and prints a fake positive.
- **Incumbent (4.2)** — widening an axis takes share from its incumbents. Matched baseline does not
  help; the share genuinely fell.

They compose into **one input**: `baselineStart = max(tag's first reference, axis regime start)`.
`velocityFromCounts` is untouched — it stays the single definition; only the denominator changes.

**Measured live at the 09-26 window:** LiquidGradients **+0.90 locked → −0.32 matched, a −1.22
shift, sign flipped** (recorded as −1.21 on 09-04 — reproduces on a grown library). Every tag first
referenced 08-10 shifts by **exactly 0.00**, and the correction grows monotonically with how late a
tag arrived. That is the signature of a real correction, not a rescale.

`tag_velocity_counts_matched` is a **sibling** of the live RPC, not a replacement. `axis_regimes` is
empty until graduation.

## Environment gotchas (hard-won — do not rediscover)

**New this session:**
- **Anthropic API credits are separate from a Claude Pro subscription.** The classifier died with
  `400 invalid_request_error: "Your credit balance is too low"` and the old button reported
  "Started — 20 clips processing" for 25 minutes while writing nothing.
- **A background job that cannot report its own failure is worse than a slow one.** The first clip
  of every batch is now classified **inside the request** so its error reaches the screen; only then
  do the rest go to `after()`.
- **But a probe that aborts on ANY failure is the opposite bug** — one dead image URL blocked all 78
  clips behind it. Per-clip image failures **park**; account-level failures **abort**. Unknown
  errors abort deliberately: parking on an error we do not understand would quietly drain the queue.
- **`create or replace function` cannot change a return type.** `drop function` first, then
  re-`grant`.
- **Postgres grants `EXECUTE` to `PUBLIC` by default** — new write-path RPCs land reachable by
  `anon` unless revoked.
- **WebFetch caches 15 minutes per URL.** A just-deployed page can read stale; a fresh query string
  gets a fresh fetch. Nearly caused a false bug report.
- **JSX strips leading whitespace on wrapped lines** — bit again, rendering "1 CLIPTHE CLASSIFIER
  CAN'T READ". Use explicit `{" "}`. (Same bug as "danysegvclips".)
- **Claude-in-Chrome tab IDs go stale between turns**; `ref_`-based clicks can silently miss where a
  coordinate click works. Screenshot immediately before clicking.
- Pinterest (`i.pinimg.com`) and `londonartfair.co.uk` are blocked by browser domain permissions.

**Carried forward:**
- **`device_bash` runs in a Linux VM, not macOS.** It cannot run `npm run dev`/`build` (no SWC for
  linux/arm64 against macOS `node_modules`) and has **no network route to Supabase**. It CAN run
  `tsc`, `eslint`, `npm test`, `node`, `python3`, `git`. **The build must run on the Mac.**
- **The mount cannot `unlink`.** `rm`, `git mv`, `git checkout` fail with "Operation not permitted".
  Plain `mv` works — sweep `.git/index.lock` and `.git/HEAD.lock` to `*.lock.trash.$RANDOM`.
  `app/taxonomy/` is an empty directory that could not be removed; `rmdir app/taxonomy` on the Mac.
- Commits from the bridge need `git -c user.name=... -c user.email=...` inline.
- **Every scripted string replacement must `assert old in s` first.** A guard on the bare word
  `"/taxonomy"` also matched the import `"@/lib/taxonomy-freeze"` — guard on the exact string.
- **`project_write` has no in-place patch** — a project doc must be rewritten whole.
- **PostgREST caps rows at 1000 without erroring** and serialises `bigint` as a string —
  `Number()` once, at the boundary.
- **Daniela does every `git push` herself. Never authenticate as her.**

## Corrections logged this session
- **"All eight RPCs need the filter" was wrong — seven do.** `unclassified_clips` is a write-path
  work queue, not a published metric; filtering it makes a clip carrying only incubating tags look
  unclassified forever and re-bills on every batch.
- **"Make the prompt say eight axes" was wrong — it is seven.** The classifier never sees
  `format_motion`. The axis count is now derived from the loaded taxonomy, so it cannot drift again.
- **A bare `add column published_at` would have broken production.** It leaves all 21 incumbents

  would have zeroed the board. They were backfilled with `created_at`.
- **`classifyAndTagClip` upserts on `(clip_id, tag_id)`** — re-running it on a tagged clip does not
  *replace* the layout tag, it adds a second one. That is why the backfill writes incubating tags
  only. A test asserts the full classifier is reachable from `app/clip/actions.ts` alone.
